# Evidence bot — наш аналитик поверх шаблона Metaculus

Клон `Metaculus/metac-bot-template` (коммит da5de87, forecasting-tools 0.3.4)
плюс наш слой. Шаблонный `main.py` не изменён — обновления шаблона можно
подтягивать без конфликтов.

## Что добавлено

| Файл | Роль |
| --- | --- |
| `evidence_bot/ledger.py` | Реестр доказательств: статьи получают ID `E1…`, дату и источник; реестр сериализуется в строку research и разбирается обратно без потерь |
| `evidence_bot/analyst.py` | Контракты аналитика и проверяющего (JSON-схемы), проверка ссылок, сжатие к внешнему взгляду, текст комментария. Без сети и без SDK |
| `evidence_bot/news.py` | AskNews: структурированные статьи (заголовок, дата, домен), 1 вызов квоты на вопрос |

## Как считается прогноз (вопросы YES/NO)

1. **Исследование.** AskNews ищет свежие статьи по тексту вопроса; каждая
   получает ID и дату. Без ключей AskNews реестр пуст, и итог — оценка
   аналитика без сжатия (см. п. 5).
2. **Аналитик** (Qwen, строгий JSON): внешний взгляд (класс событий и его
   базовая частота), статус-кво, утверждения со ссылками на `E#`,
   неопределённости, вероятность. Цены рынка и прогноза сообщества он не видит.
3. **Проверка ссылок кодом.** Ссылка засчитывается, только если ID существует
   и статья опубликована не позже момента прогноза. Статьи без даты и
   «из будущего» не считаются.
4. **Проверяющий** (отдельный вызов, temperature 0): по каждому утверждению —
   подтверждает ли его цитата; плюс критические ошибки рассуждения (неверное
   прочтение критериев, двойной счёт, утверждение, что вопрос уже решён).
   Отсутствие ссылок он не считает ошибкой — это учитывает код. Своей
   вероятности не даёт.
5. **Сжатие.** Вес = 0.5 + 0.5 × доля подтверждённых утверждений; ×0.5, если
   проверяющий отклонил. Итог в логит-шкале сдвигается от внешнего взгляда
   к оценке аналитика на этот вес. Проверка может только вернуть прогноз к
   базе, но не увести дальше. Коэффициенты — стартовые, не подобранные:
   калибровать по разрешённым вопросам.
   **Сжатие работает только при непустом реестре.** Если новостей нет, ссылаться
   не на что, и нулевая доля подтверждённых ничего не говорит о прогнозе: итог =
   оценка аналитика целиком (вес 1), даже если проверяющий нашёл ошибку —
   она остаётся в журнале и комментарии.
6. **Ансамбль.** Шаблон делает 5 прогнозов на вопрос и берёт медиану.
7. **Комментарий** (обязателен по правилам) — сводка, внешний взгляд,
   утверждения с источниками и пометкой «засчитано / не засчитано», числа.

Многовариантные, числовые, даты и условные вопросы — промпты шаблона на Qwen.

## Теневые варианты (журнал, не отправляются)

Считаются один раз на вопрос, ошибка в тени не мешает основному прогнозу:

- `template` — промпт шаблона на той же модели (базовая линия);
- `no_research` — наш конвейер с пустым реестром, то есть оценка аналитика без
  сжатия (польза новостей вместе со сжатием).

Ещё два варианта берутся из журнала основного прогноза бесплатно:
`raw_probability` (без проверки и сжатия) и `prior` (только внешний взгляд).
Прогноз сообщества пишется в журнал для оценки, аналитику не передаётся.

## Запуск локально

```powershell
cd C:\Users\shokl\Downloads\гомаркет\metaculus_bot
copy .env.template .env   # затем вписать ключи в .env (файл в .gitignore)
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -t .
.\.venv\Scripts\python.exe -X utf8 evidence_main.py --mode test_questions
```

Переменные: `METACULUS_TOKEN` (новый ключ бота), `NORDROUTER_API_KEY`;
по желанию `ASKNEWS_API_KEY` (или `ASKNEWS_CLIENT_ID` + `ASKNEWS_SECRET`),
`NORDROUTER_VERIFIER_MODEL` — проверяющий на другой семье моделей,
`NORDROUTER_MODEL` — сменить основную модель.
`NORDROUTER_MAX_IN_FLIGHT` (по умолчанию 2) — сколько вызовов одновременно:
NordRouter отвечает 429 «too many requests in flight», если превысить лимит.
`NORDROUTER_REASONING_EFFORT` (по умолчанию `none`) — со скрытыми рассуждениями
Qwen тратит 2–3 тыс. токенов и 60–160 с на вызов; `reasoning.enabled=false`
NordRouter игнорирует, работает только `reasoning_effort`.

Без `--publish` прогнозы только считаются и пишутся в `journal/` и `reports/`.

- `test_bot.yaml` (вручную): `evidence_main.py --mode test_questions --publish` —
  публикует только в тестовую зону `bot-testing-area`.

  (включено 15.10.2026). Турниры заданы явно (`fall-futureeval-2026`,
  `minibench`); сменить сезон — переменная `METACULUS_SEASON_SLUG`.
- `run_bot_on_metaculus_cup.yaml`: расписание выключено, Cup не в плане.
- `keepalive.yaml`: пустой коммит 1-го и 15-го числа — GitHub выключает
  расписания в публичных репозиториях после 60 дней без активности.
- `review_bot.yaml` (по понедельникам): разбор разрешённых прогнозов шаблоном
  Metaculus, нужен только `METACULUS_TOKEN`.
- Журнал и отчёты сохраняются как артефакт запуска на 90 дней.
- Секреты: `METACULUS_TOKEN`, `NORDROUTER_API_KEY`, `ASKNEWS_API_KEY`;
  переменная (Variables) `NORDROUTER_VERIFIER_MODEL` — по желанию.

## Что не проверено

- Пробный прогон 15.10.2026 (`test_questions`, без публикации): 9 вопросов
  из 9, ~10 минут, строгий JSON через litellm работает. Не проверены: AskNews
  (ключа ещё нет) и сама публикация комментария.
- Учёт стоимости: litellm не знает цену Qwen, поэтому стоимость в отчётах
  `forecasting-tools` может быть нулевой или неверной. Реальный расход
  смотреть в кабинете NordRouter.
- Если провайдер не поддерживает strict json_schema, убрать `schema` в
  `build_llms()` — парсер терпит обрамление вокруг JSON.

## Особенности турнира и известные риски

- Вопросы осеннего турнира открыты для прогноза ~3 часа; бот заходит каждые
  20 минут и пропускает уже спрогнозированные.
- Оба турнира идут в одном цикле asyncio: семафоры шаблона привязываются к
  первому циклу, второй `asyncio.run` падал бы на поиске новостей.
- Длинные прогоны: пачка MiniBench (~60 вопросов) при лимите 2 одновременных
  вызова NordRouter может идти больше часа; следующие запуски ждут в очереди.
- Аналитик иногда подкрепляет утверждение всеми статьями реестра сразу —
  код такие ссылки засчитывает; смотреть при разборе журнала.
- Журнал хранится как артефакт 90 дней — для разбора за весь сезон скачивать
  артефакты заранее (`gh run download`).
